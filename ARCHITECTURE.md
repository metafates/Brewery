# Brewery — Architecture

A native macOS GUI for Homebrew. SwiftUI, macOS 26, zero third-party dependencies. This document is the current-state spec: features are designed here before implementation, every behavioral claim about Homebrew is verified against the brew 6.x source (`Library/Homebrew/…` paths cited, rooted at `$(brew --repository)` — Homebrew ships as a git checkout, so no separate clone is needed; the line numbers were read against brew 6.0.15 and drift with releases, so grep the symbol rather than trusting the number), and the document is rewritten in place as the system changes rather than appended to as a changelog.

## What Brewery is

**Goals**

1. Fast fuzzy search over the full Homebrew catalog (formulae + casks), including packages from installed third-party taps.
2. The package lifecycle: install, upgrade (per item + Update All), uninstall — confirmed, force-less — and cask zap for casks whose receipt earned it.
3. Taps managed end to end: local scan into the catalog, add/remove, the trust spectrum surfaced and one guarded trust write.
4. Services: list with live status, start/stop through the operation queue, the catalog's `service` block rendered human-readably.
5. Reports: Orphans (what `autoremove` would remove), Attention (deprecated/disabled installed packages), Storage (what brew spends on disk + `brew cleanup`), Checkup (`brew doctor` on demand, findings rendered structurally with native remediation where safe).
6. Package identity everywhere: homepage favicons, installed-app bundle icons, GitHub avatars, SF Symbol fallbacks.
7. App Store-like cards for browsing, state rows for reports and services; native macOS look per Apple HIG throughout.
8. Simple, maintainable code. KISS and YAGNI.

**Non-goals**

- No destructive brew capability beyond the confirmed whitelist ([Safety](#safety)): no `--force`, no `--ignore-dependencies`, no cleanup flags (`--prune`, `-s`/`--scrub`, named targets), no services `kill`/`cleanup`/`restart`/`run`/`--file`/root, no `untap --force`, no `--custom-remote`/`--repair`/`--eval-all`, no raw-argument path anywhere.
- No analytics-based popularity *ranking* in search — install counts display in the pane and order browsing, but never feed the scorer.
- No Settings scene, no second primary window, no log persistence across launches.
- No dependency *graph visualization* — flat dependency/dependent lists from install receipts.
- No App Store distribution: the app execs `brew` and cannot be sandboxed.

## How Homebrew actually works (verified against brew 6.x source)

### Catalog data

- formulae.brew.sh serves full catalogs: `GET /api/formula.json` (~8.5k formulae, ~30 MB uncompressed) and `GET /api/cask.json` (~7.7k casks, ~17 MB; both gzipped over the wire). Entries carry `name`/`token`, `desc`, `homepage`, `versions.stable`/`version`, `deprecated`/`disabled` plus their dates, preset-or-prose reasons and replacement fields, cask display `name` array, `caveats` (may embed a literal `$HOMEBREW_PREFIX` — verified on `php`), formula `conflicts_with` + `conflicts_with_reasons` (parallel arrays; verified on `vim`), cask `conflicts_with` (an object — brew 6's DSL accepts only the `cask` key, `cask/dsl/conflicts_with.rb:12`), cask `artifacts` and `depends_on.formula`, and the formula `service` block.
- brew 6.x's own local API cache moved to an *internal* per-arch format (`internal/packages.<tag>.jws.json`, built in `api/internal.rb` — undocumented, not a public contract); the legacy JWS files are no longer refreshed. **The GUI therefore downloads `formula.json`/`cask.json` from formulae.brew.sh itself** rather than parsing brew's cache.
- **Command database**: brew's `command-not-found` data — which executables each formula installs — comes from the internal API's per-formula `executables` array (`api.rb:282-309`, published per `api.rb:314`); formulae.brew.sh serves the same file publicly at `GET /api/internal/executables.txt` (~350 KB, `name:cmd1 cmd2 …` per line, verified live). If the endpoint moves, the feature degrades to hidden.
- **Analytics**: `GET /api/analytics/install/90d.json` (2.4 MB, ~32k items including tap formulae by qualified name) — **counts are comma-formatted strings**. Casks: `GET /api/analytics/cask-install/homebrew-cask/90d.json` — the top-level key really is `formulae` (historical misnaming) and it's a dict, not an array. Both verified live.

### Taps

- **Location**: `<brew repository>/Library/Taps/<user>/homebrew-<repo>` — the *repository*, not the prefix (they differ on Intel; `bin/brew:83-108`). The directory listing **is** the tap list: `brew tap` with no args is a pure-bash iteration of exactly this directory (`tap.sh`). Tap name = lowercased `<user>/<repo minus homebrew->` (`tap.rb:293-303`).
- **Formula discovery** (`tap.rb:954-1031`): the formula dir is the **first existing** of `Formula/`, `HomebrewFormula/`, tap root — never a union; recursive in the first two, top-level-only at root. Casks: always `Casks/**`. Duplicate basenames: longer path wins.
- **Naming across commands**: `brew list --formula --versions` prints **short** keg names for tap items (`cmd/list.rb:307-312`); `brew outdated --json=v2` reports formulae by tap-qualified `full_name` but casks by short token (`cmd/outdated.rb:196-216`). Both normalize through `shortName` — the join rule survives taps unchanged.
- **Resolution order** (`formulary.rb:1230-1248`): the API loader precedes tap loaders, so a bare short name always resolves to homebrew/core when core has it — **qualified names are mandatory** for anything tap-scoped. Hazard: a qualified name whose tap is *not installed* makes brew clone the tap on demand (`cmd/install.rb:195-203`) — an implicit mutation the scan-membership guard exists to prevent.
- **Trust gate**: `HOMEBREW_REQUIRE_TAP_TRUST` defaults **on** (`env_config.rb:654`). Loading an untrusted tap's formula raises unless the fully-qualified name appears verbatim in argv (`trust.rb:560-570`), and `install`/`upgrade` with qualified names **auto-trust the item persistently** (`cmd/install.rb:204`, `trust.rb:116-145` — a durable write to `~/.config/homebrew/trust.json`). Flip side: `Formula.installed` swallows load errors (`formula.rb:2649-2655`), so an installed formula from an *untrusted* tap silently vanishes from `brew outdated` and `services list`.
- **Trust store**: XDG-resolved `trust.json`, atomic writes → safe to read directly; keys `trustedtaps`/`trustedformulae`/`trustedcasks`/`trustedcommands`, values lowercased. Custom-remote taps store normalized URLs, so the reader tolerates URL-shaped entries and treats anything unmatched as untrusted. Official taps are implicitly trusted and never stored (`tap.rb:1489-1491`); partial trust = any item entry prefixed `tap/` (`trust.rb:290-295`).
- **`brew tap user/repo` cannot hang or surprise**: one-arg form always clones `https://github.com/user/homebrew-repo` (`tap.rb:408-410`), brew sets `GIT_TERMINAL_PROMPT=0`, and `Ask.confirm?` short-circuits to false on non-TTY stdio (`ask.rb:13`) — brew 6 has no interactive prompt anywhere on piped stdio. Progress goes to **stderr**; already-tapped exits 0 silently (the post-op rescan is the truth); tapping never writes trust (`description_cache_store.rb:89` rescues `UntrustedTapError` before eval).
- **`brew untap user/repo` is self-guarding**: with installed packages from the tap it refuses and exits 1 having deleted nothing (`cmd/untap.rb:60-66` + `ask.rb:13`). Plain untap deletes the clone, symlinks and cache entries (`tap.rb:869-909`). **Trust entries survive untap** and reapply on re-tap — disclosed in the removal dialog. `untap --force` uninstalls the tap's kegs first — unrepresentable here.
- **Tap metadata without Ruby**: `desc`/`homepage`/`version`/`license` stanzas and `deprecate!`/`disable!` are line-anchored string literals a regex can extract; `version` is frequently implicit (`Version.detect`'s heuristics — not reimplementable), so extraction is best-effort by design. Remotes come from `remote.origin.url` in `.git/config` (`tap.rb:406-410`; custom remotes exist — read, never assume). `.git/FETCH_HEAD` mtime = "last checked" (`cmd/update.sh:905`). `brew tap-info --json` is a trap (a GitHub API call per tap) and is never used. A core tap kept as a git clone must be excluded from scanning — the API catalog already covers it.

### Services

- `brew services` is in brew core (`Library/Homebrew/services/`). Subcommand aliases are accepted verbatim — the whitelist emits canonical tokens only.
- **`start` vs `run`** (`services/cli.rb:95-162`): `start` copies the plist into `~/Library/LaunchAgents` + enable + bootstrap — a login item; `run` dies at logout. The GUI exposes `start`/`stop` only; a toggle is a persistence statement. **`stop` deletes the registered plist** (`cli.rb:242`) — brew's own inverse of `start`, fully reversible.
- Sharp edges, all unrepresentable: `cleanup` (kills orphans + deletes plists), `kill`, `--file=`, `--sudo-service-user`, root invocation (`take_root_ownership?` chowns the keg to root, `cli.rb:288-352`).
- **`brew services` never invokes sudo** (no `sudo: true` caller in the tree) — it cannot hang on a password prompt. A `require_root` formula started as a user warns and proceeds (`cli.rb:378-383`), then fails at runtime — so the GUI disables the toggle for `require_root` services instead of offering a start that lies.
- **`services list --json`** → exactly `{name, status, user, file, exit_code}` (`subcommand/list.rb:42`); `status` ∈ `started · stopped · none · scheduled · error · unknown · other` (`formula_wrapper.rb:322-340`). ~0.5 s measured — the `brew outdated` cost class, never on a render path. **Exit codes lie** ("not started" warns and exits 0, `cli.rb:190`) — statuses are re-read after every mutation.
- The `service` block (`service.rb:715-767`): `run` (string *or* array), `run_type` ∈ `immediate`/`interval`/`cron`, `keep_alive` (object of booleans), `require_root`, `log_path`, `sockets`, etc. Paths embed `$HOMEBREW_PREFIX`. Services never trigger auto-update (`utils/auto-update.sh:144-155`); `HOMEBREW_SERVICES_NO_DOMAIN_WARNING=1` is set on every invocation.

### Installed state

- `brew list --formula --versions` / `--cask --versions` — plain text `name v1 [v2 …]` per line, pure Bash (`list.sh`), sub-second. The `--formula` token is required: bare `brew list --versions` prints casks alongside formulae (verified live), which would double-key every cask. **The version list is unordered**: the `--versions` path falls through to Ruby, which prints `d.subdirs` and `Pathname#subdirs` is a bare `children.select(&:directory?)` (`extend/pathname.rb`) — readdir order, while brew sorts where it cares (`Utils::Path.formula_installed_prefixes` ends `.sort_by(&:basename)`). Measured on a 10-rack machine, 4 racks came back newest-first. Every consumer reads `versions.last` as the live keg, so `parseListVersions` sorts numerically at the one parse site; the recorded ceiling is that a string sort is not brew's `PkgVersion`, so a `HEAD-<sha>` keg sorts last whatever is linked.
- `brew outdated --json=v2` → `{formulae: [{name, installed_versions, current_version, pinned, pinned_version}], casks: […]}`. **The bare form exits 0 even when items are outdated** — but `brew outdated <name>` exits 1 when that item is outdated (`cmd/outdated.rb:90`); the app only ever runs the bare form. The section mirrors bare `outdated`'s non-greedy default: `version :latest` casks never appear, `auto_updates` casks only when the installed bundle lags — the `--greedy` variants are out of scope (those apps update themselves).
- Prefix: probe `/opt/homebrew/bin/brew`, then `/usr/local/bin/brew`; the prefix is the binary's grandparent — the same rule `bin/brew` uses.

### Install receipts

- `Cellar/<name>/<version>/INSTALL_RECEIPT.json`: `installed_on_request` (absent = `false`, per brew's `tab.rb`) and `runtime_dependencies` — an array of `{full_name, version, declared_directly}` covering the flattened runtime closure at install time. `poured_from_bottle` feeds the orphan report (brew only autoremoves bottles). `time` (unix seconds) feeds the install-date sort.
- `Caskroom/<token>/.metadata/INSTALL_RECEIPT.json`: has `installed_on_request` too, but `runtime_dependencies` is an **object**, not an array (observed `{}`) — only `installed_on_request` is read; cask deps come from the catalog's `depends_on.formula`. `uninstall_artifacts` names the `.app` bundles the cask put on disk (heterogeneous array; only `app` entries read) — the source for the pane's Open — and a `zap` entry records whether a zap stanza exists.
- Receipts are snapshots that can drift from today's `brew deps`; intersecting with the live installed set prunes stale entries. `brew deps`/`brew uses` were rejected: Ruby startup per call for an answer the receipts already hold as local file reads.

### Driving brew from a GUI

- **The login-shell overlay.** A Finder-launched app inherits launchd's environment, and brew reads real configuration from the environment: the trust store and user `brew.env` resolve through `XDG_CONFIG_HOME` (`bin/brew:163-170` → `HOMEBREW_USER_CONFIG_HOME`, `trust.rb:27-34`), doctor's PATH checks judge the launch PATH (`diagnostic.rb:496-582` via `ORIGINAL_PATHS`), and remediation one-liners pick shell syntax from `SHELL` (`utils/shell.rb:24-30`). Observed cost of not doing this: with `XDG_CONFIG_HOME` missing, every terminal-trusted tap read as untrusted — Checkup grew spurious findings **and brew silently ignored those taps' formulae for every command the app ran**. `LoginEnvironment` captures the login shell's environment once per launch (`getpwuid` shell → `$SHELL` → zsh; `-l -c "printf '\0'; env -0"` — the NUL sentinel discards dotfile noise, NUL-delimited records survive newlines in values; 3 s timeout, then SIGTERM + a pipe close, SIGKILL a second later) and overlays a **whitelist** onto every brew child: `PATH`, `SHELL`, `XDG_CONFIG_HOME`/`XDG_CACHE_HOME`/`XDG_DATA_HOME`, the five lowercase proxy names, and every `HOMEBREW_*` var — the names brew itself consumes (`bin/brew` `USED_BY_HOMEBREW_VARS`), nothing else. The proxy names are the one set `USED_BY_HOMEBREW_VARS` does *not* cover: `env_config.rb` declares `http_proxy`/`https_proxy`/`all_proxy`/`ftp_proxy`/`no_proxy` lowercase, `build_environment.rb`'s `KEYS` carries them into every build, and `brew(1)` documents them as how Homebrew is used behind a proxy — so without them a proxied Mac downloads the catalog fine (URLSession honors the system proxy) and fails every install. The **timeout is load-bearing and was once unreachable**: the surviving task-group child parks in `await reader.value`, which ignores the awaiting task's cancellation, so `cancelAll()` could not unwind the group's implicit await-all and everything after it was dead code — a dotfile slower than 3 s, or one that backgrounds a process inheriting stdout, wedged the capture and with it every brew invocation. The deadline child therefore forces EOF itself (terminate *and* close), and the `PATH == nil` guard is what stands between a truncated capture and a bad PATH. Merge order is the contract: GUI base → overlay (terminal parity) → the forced vars below last, because they are safety guarantees. PATH passes **verbatim** — brew is exec'd by absolute path, and a genuinely misordered PATH should surface in Checkup exactly as in a terminal. Capture failure degrades to an empty overlay. `TrustStore` reads through the same resolution, and freshness/Storage measurements resolve `HOMEBREW_CACHE`/`HOMEBREW_LOGS` against `effectiveEnvironment` — the environment the *next* brew child actually gets.
- **Environment forced on every invocation**:
  - `HOMEBREW_NO_ENV_HINTS=1` — silences hint noise.
  - `HOMEBREW_NO_ASK=1` — belt-and-braces; brew's ask-mode already auto-skips on non-TTY stdio (`ask.rb`).
  - `HOMEBREW_NO_AUTO_UPDATE=1` — skips the git auto-update *and* the API refresh; the auto-update path `exec`s a fresh brew mid-run (`utils/auto-update.sh`), which would restart our output stream. The freshness rule below compensates for the staleness this causes.
  - `HOMEBREW_NO_INSTALL_CLEANUP=1` — **part of the non-destructive guarantee**: by default install/upgrade auto-clean old kegs and periodically run a *full* cleanup (`env_config.rb:586`). The whitelist covers what we ask brew to do; the env vars cover what brew does unasked.
  - `HOMEBREW_NO_AUTOREMOVE=1` — `brew uninstall` implicitly runs `autoremove` afterwards (`cmd/uninstall.rb:133`, gated per `env_config.rb:522`; `brew cleanup` too, `cleanup.rb:411-412`). Suppressed: a removal is exactly what the user chose; the orphans it creates surface in the Orphans report with their own confirmation. The explicit `.autoremove` command is unaffected (`cmd/autoremove.rb:22`).
  - `HOMEBREW_SERVICES_NO_DOMAIN_WARNING=1`; `SUDO_ASKPASS=<helper>` on mutating commands.
- **User config can override us**: `bin/brew` loads `brew.env` files and exports any `HOMEBREW_*`/`SUDO_ASKPASS` line, protecting only variables it sets itself — a user's `brew.env` beats our env. Treat our env vars as defaults, not invariants.
- **Sudo (pkg casks)**: with piped stdio sudo has no TTY — unless `SUDO_ASKPASS` names an executable, in which case brew adds `-A` itself (`system_command.rb:296-312`). A cancelled dialog fails fast with a readable `Error:` line.
- **Concurrency**: mutating commands take non-blocking flocks in `var/homebrew/locks/` — a second concurrent mutation errors immediately rather than queueing. The GUI serializes all mutations in a FIFO queue; reads run concurrently.
- **Exit codes**: 0 ok, 1 failure (stderr carries `Error:`/`Warning:` lines), 130 on SIGINT. **Output**: pipes are not TTYs, so no color by default — but a user `brew.env` can force `HOMEBREW_COLOR=1`, so ANSI escapes are stripped at log ingest.
- `brew install X` on an installed-but-outdated `X` acts as an upgrade unless the user set `HOMEBREW_NO_INSTALL_UPGRADE` (`cmd/install.rb:32`) — acceptable either way, both are on the safe list.

### Metadata freshness

With auto-update disabled, brew's metadata freezes — and `brew outdated` computes against the frozen cache, so Outdated could claim "everything is up to date" for days while a terminal disagreed. Verified facts:

- `outdated` is on the auto-update trigger list (`utils/auto-update.sh:150-156`), and for those commands brew refreshes the API payload when older than **450 s** (`api.rb fetch_api_files!` → `HOMEBREW_API_AUTO_UPDATE_SECS` default, `env_config.rb:57`) — the parity target. Under `HOMEBREW_NO_AUTO_UPDATE` the cache is never refreshed at any age (`api.rb:209-221`).
- brew answers everything from `$HOMEBREW_CACHE/api/internal/packages.<tag>.jws.json` (`api/internal.rb:30-31,65-66`; cache default `~/Library/Caches/Homebrew`, `utils/os.sh:55`), and touches its mtime **only after a successful download or revalidation** (`api.rb:141-146`) — the mtime *is* "when metadata was last known good", terminal and GUI runs alike.
- An *explicit* `brew update` is not gated by `HOMEBREW_NO_AUTO_UPDATE` (only the auto-update path checks it), and holds a non-blocking exclusive flock (`cmd/update.sh:679`) — a concurrent second update errors immediately.

**The rule** (`AppModel`, thresholds in `BrewClient`): before the app reads `outdated` (launch, ⌘R) or mutates packages, the newest payload mtime must be within brew's own 450 s window, else an inline `.update` runs first. Mechanically: staleness is re-stat'd on every `refreshState()`, so a terminal-side update counts and the app skips a redundant one. At *launch*, probes run first (cached answers on screen in ~1 s), then a stale cache triggers one update + re-probe — the page corrects itself non-modally. On *⌘R* the update runs before the probes — one landing beats swapping answers mid-refresh — and ⌘R checks **unconditionally**: 450 s is brew's *auto*-update coalescing rule, while an explicit check always runs (App Store's Check for Updates never answers "recent enough"). *Mutations* inject "Updating Homebrew" ahead of themselves only when metadata is actually stale and no update is pending. The inline check is the one mutating argv that runs outside the operation queue — `pump()` holds while it runs, so the flock can never bite. Failure is silent: offline falls back to the cached answer, with an in-app attempt timestamp backing retries off to one per window.

**UI**: Outdated carries a footnote caption — "Checking for updates…" beside a spinner, else "Last checked *n* ago". The caption ticks every second but reads at minute granularity (`.everyMinute` failed twice: ticks are wall-clock boundaries not anchored to the mtime, and on macOS it empirically never fired; `FreshnessCaptionTests` pins the bucketing, including the clamp that stops a minute-floor tick phrasing the past as "in 30 seconds"). While the section is empty and any state work runs — the launch re-probe, ⌘R, the background check, a post-mutation reconcile, the catalog download — the empty state shows the working capsule instead of claiming "Everything is up to date". That is one instance of the app's one loading rule: **the work never takes the content.** A refresh never dims, blurs or disables what is on screen — stale listings stay sharp and interactive while they are re-checked (HIG *Loading*: let people do other things while they wait; a veil that blurred and `.disabled`d both columns used to do the opposite, with per-surface gating that left the inspector veiled over an empty listing and nothing veiled at all during a cold load). The one global tell is the toolbar Refresh glyph, spinning on `AppModel.isChecking` — a composed signal (⌘R ∨ the inline update ∨ the catalog download ∨ any in-flight `refreshState()` pass; pure `AppModel.checking`, pinned by `CheckingSignalTests`), so background work spins it too. A wait may only occupy space that has nothing to show: an empty section *replaces* its claim with the capsule (each listing view's `isChecking`), a row-sized slot wears the inline spinner-caption (the Taps "Your Taps" section, the Checkup header), and value slots redact — claims are replaced, never overlaid.

### Uninstall

- **Flags** (`cmd/uninstall.rb:19-41`): Brewery uses only the kind flags and `--zap`; brew itself declares `conflicts "--formula", "--zap"` (`cmd/uninstall.rb:38`) — why the `.zap` case hard-codes `--cask`.
- **Dependents**: brew refuses **before removing anything** for formulae (`uninstall.rb:22-27`), exit 1, naming kegs by absolute Cellar path (`dependents_message.rb:22-43`). The check counts **installed cask dependents** too (`installed_dependents.rb:45`) — the app's receipt-built dependents map is formula→formula only, so the UI's block list unions in installed casks' catalog `depends_on` claims, and brew stays the final arbiter.
- **Pinned = silent no-op**: skipped with `onoe`, which does not set `Homebrew.failed` — **exit 0 having removed nothing** (`uninstall.rb:46-48`, `cask/uninstall.rb:42-45`). Exit codes cannot be trusted; the UI blocks pinned packages before anything enqueues.
- **Multiple versions** — the common case under `NO_INSTALL_CLEANUP=1`: default-keg resolution picks opt symlink → linked → sole → latest (`cli/named_args.rb:557-581`); uninstall removes only that keg, exits 0, and suggests `--force` for the rest (`uninstall.rb:60-68`). Disclosed in the dialog; a second uninstall peels the leftover.
- **Zap**: dispatches the zap stanza, then always purges the whole `Caskroom/<token>` (`cask/installer.rb:694-708`). The stanza may delete settings and "files which are shared between applications" (`docs/Cask-Cookbook.md:1312-1315`) — the dialog's second tier carries that warning. A stanza-less cask gets no zap offer.
- **Residue**: `etc/` config files are warned about but left; uninstall also unpins the formula (`uninstall.rb:59`) and untrusts removed tapped items brew-side (`cmd/uninstall.rb:122-127`) — and `--force` uninstall unpins *without* the pinned refusal (`uninstall.rb:41`; casks silently unpin under force, `cask/uninstall.rb:38-49`), moot here since `--force` is unrepresentable. Cask uninstall directives escalate through the existing askpass helper.

### Pinning

- **Two ledgers, plain directories**: `$HOMEBREW_PREFIX/var/homebrew/pinned` (formulae, `startup/config.rb:54`) and `pinned_casks` (`config.rb:57`). Each entry is a **bare short name/token** — never tap-qualified (`formula_pin.rb:15` pins `.name`, not `.full_name`; `cask/cask.rb:347`) — a relative symlink to the newest installed keg/version dir (`formula_pin.rb:20-30`, `cask/cask.rb:312-319`). Created lazily, removed when empty (`extend/pathname.rb:195-207`): **a missing directory means zero pins, not an error.** Every brew producer resolves pins from these directories (`cmd/list.rb:282,290`, `list.sh:123-128,166-167`), which is why the app's truth is a direct scan rather than a subprocess.
- **Casks are pinnable since brew 5.1.12** (`cmd/pin.rb:23-28`; commit `7a07806658` added cask pinning *and* the explicit `--formula`/`--cask` switches, `pin.rb:21-26`, `unpin.rb:17-22`). An `auto_updates` cask warns it may self-update regardless (`pin.rb:42-45`).
- **Dangling-pin semantics differ by kind**: a formula is `pinned?` while the symlink *exists* — dangling still blocks upgrade and uninstall (`formula_pin.rb:40-42`); a cask requires the target to exist too (`cask/cask.rb:329-331`). The app's scan mirrors both.
- **Exit codes**: repeat pin warns and exits 0 (`pin.rb:36-37`); pin of a not-installed package fails, exit 1 (`pin.rb:38-39`); **unpin never fails** (`unpin.rb:35-47`). Bare `upgrade` skips pinned with a warning, exit 0 (`cmd/upgrade.rb:391-392,435-443`); `upgrade <pinned>` fails exit 1; `install` and `reinstall` of a pinned package refuse with **exit 0** (`install.rb:134,226`; `cmd/reinstall.rb:161,176`) — the pinned-uninstall trap's family.
- **autoremove is pin-blind**: candidate selection ignores pins entirely (`utils/autoremove.rb:15-19`), so a pinned leaf is listed as "Autoremoving …" and then the uninstall refusal fires — error text on stderr, package still installed, **exit 0** (`cleanup.rb:941-949` → `uninstall.rb:47`). `brew migrate` carries pins across renames (`migrator.rb:178-181,271`); cleanup skips only the pinned keg itself.
- **In the app**: pin state is the union of the ledger scan (`PinStore.scan`, the fourth refresh probe — the outdated payload's `pinned` flag only covers outdated packages) and that payload flag. `.pin`/`.unpin` are whitelisted with explicit kind tokens on link's admission bar: named, non-destructive, mutually inverse, **no confirmation** (the service-toggle rule) — which also means no ellipsis anywhere in their titles.

### Cleanup

- **What no-args `brew cleanup` removes** (`cleanup.rb:398-436`): per-formula old kegs, version-stale downloads, logs older than 30 days effective (`cleanup.rb:541`), locks, orphaned `.pyc`, broken prefix symlinks. Linked, pinned and `keepme`-referenced kegs are skipped with an `opoo` (`formula.rb:3654-3658`) — those stderr lines are correct, not errors.
- **The landmine, pre-dulled**: plain `cleanup` also runs `autoremove` — *uninstalls packages* — at `cleanup.rb:412`, gated by the app-wide `HOMEBREW_NO_AUTOREMOVE`. Our cleanup removes files, never packages.
- Nothing to clean → exit 0, empty stdout; removals end with "freed approximately X" (`cmd/cleanup.rb:55-60`); exit 1 only on keg permission errors. The banned `--prune` *disables* the content-aware staleness check (`cleanup.rb:663`) and `--prune=all` wipes the cache regardless of what's installed.
- **`.cleaned` marker**: `HOMEBREW_CACHE/.cleaned` mtime records the last full clean; an explicit no-args run touches it too (`cleanup.rb:427`). Paths (`utils/os.sh:53-57`): cache `~/Library/Caches/Homebrew`, logs `~/Library/Logs/Homebrew`, each overridable — the app resolves them through `effectiveEnvironment` so what it measures is what its spawned brew will sweep.

### Doctor

- **`--json` is hidden but structured** (`cmd/doctor.rb:25-27`, emitted `:89-93`): `{"tier": int|string, "findings": [{text, tier, affects, links, remediation: {commands, text}}]}` (`diagnostic/finding.rb:70-77`). `tier` is an Integer *or* Symbol → JSON string — the decoder takes both. A clean run emits `{"tier": 1, "findings": []}`, exit 0.
- **Exit 1 means findings exist, not failure** (`cmd/doctor.rb:70`) — the checkup path runs through `run` accepting exits 0 and 1 and judges success by parse, with an `onErrorLine` sink keeping stderr out of the JSON stream (belt-and-braces: first-`{`/last-`}` trim).
- Read-only in effect; **not** in `AUTO_UPDATE_COMMANDS` (`utils/auto-update.sh:143-149`); slow checks deliberately ordered last (`cmd/doctor.rb:46-50`) — runtime varies from ~2 s to a minute. `brew missing` needs no separate surface — `check_missing_deps` covers it.
- **Findings are environment-relative**: doctor judges the process environment it runs under — the login-shell overlay is what makes the app's answer describe the user's actual machine; findings that survive it are real.

### Link

- The source finding is `check_for_unlinked_but_not_keg_only` (`diagnostic.rb:1131-1161`) — keg-only formulae excluded (`:1137`), `remediation.commands` exactly one `brew link <name>` per keg, one-to-one and in order (`:1152-1158`).
- **Bare `brew link <name>` is non-destructive**: on a conflicting real file it raises and **rolls back every symlink it made** (`keg.rb:574-576`), exit 1 with a readable message. Keg-only without `--force` is a warning + no-op (`cmd/link.rb:100-104`). Reversible via `brew unlink` (not whitelisted — nothing needs it). Recorded caveat: `cmd/link.rb:107` silently unlinks formulae named in this formula's `link_overwrite` stanza (`unlink.rb:8-17`) — reversible, but a state change to other packages.
- **Remediation inventory** (survey of every `Remediation(commands:)` in `diagnostic.rb`): pure-brew shapes are link, cleanup (`diagnostic.rb:397-402`, the only cleanup emitter), untap (sometimes multi-name, `:1325-1327`), install/upgrade (`:981-987`), and `reinstall --force` (never simplified). Everything else needs sudo, `rm`, shell syntax or a TTY — copy-only forever. The untrusted-taps finding (`diagnostic.rb:903-912`) is text-only: `affects` empty, every `brew trust` line inside the prose — parsed for presentation only, never executed.

## Systems

### Data model

`Package` is pure data, `Codable`/`Identifiable`/`Hashable`: `kind` (`.formula`/`.cask`), **short** `name`, `displayName` (cask display name), `desc`, `homepage`, `version`, `deprecated`/`disabled` with dates, humanized reasons and a resolved replacement, `caveats`, `conflicts` (`[Conflict]` — name + optional reason + optional kind targeting the push), `commands` (from executables.txt), `installs90d`, `license`, `rubySourcePath`, `tap` (`"user/repo"` for third-party, **nil = core**), `artifacts` (cask contents aggregated by kind), `caskDependencies`. `id = "\(kind):\(name)"`; `isFont` = cask with the `font-` prefix. Comparators (`displayOrder`, `popularityOrder`, `sizeOrder`, `installDateOrder`) and display grammars (`attentionPhrase`, `displayCommands`) are pure statics/computed text with tests.

**Decode defensively**: `conflicts_with_reasons` contains **null elements** (5 formulae express "no stated reason" as a `null` inside the array — typed `[String]?` the whole 8.5k decode aborts), so the field is `[String?]?`; `license` and cask `conflicts_with` decode through lenient wrappers that yield nil on unexpected shapes.

Install-state overlays live in `AppModel`, keyed by `Package.ID`: `InstalledInfo` (versions, `onRequest` — missing receipt → `true`, never hide the unknown — dependencies as short names, apps, `builtFromSource`, normalized `tap`), `OutdatedInfo` (installed/current/pinned), `ServiceStatus` (`ServiceHealth` + exit code; unknown strings → `.other`), `pinned: Set<Package.ID>` (the pin-ledger scan; `isPinned` unions it with the outdated payload's flag, so a pin on a current package is visible too), plus `TapInfo` (name, remote, counts, FETCH_HEAD date) and `TrustState` from the trust store. `AppModel.status(for:)` merges them; `busy` wins, and a running `upgradeAll` marks every outdated unpinned package busy. Each refresh sweeps the receipts (`Receipts`, `@concurrent`, ~350 small JSON reads) and inverts the dependency map once into `dependents` — "who depends on X" is a dictionary lookup. Installed items missing from the catalog get synthesized `Package`s (name + kind + installed version, nil everything else) — rare now that the tap scan covers tapped items; the fallback remains for what no scan covers.

**The join rule**: `brew outdated` reports formulae by qualified `full_name`, `brew list` prints short keg names — both normalize to the last `/`-component, so an overlay key is always `kind:shortname`, matching `Package.ID`.

**The tap rules**, in one place because every consumer must agree:

- **`Package.name` stays short.** The tap is a separate field, so the ID, the joins and `shortName` are untouched.
- **Effective tap** = `installed[id]?.tap ?? package.tap` — the receipt outranks the catalog because it records what was actually installed. Display and command construction read the same rule, so what the UI claims and what brew is told never diverge. Receipt `source.tap` of `homebrew/core`/`homebrew/cask` folds to nil so "nil = core" holds everywhere.
- **Command qualification** (`AppModel.install`/`upgrade`/service methods — the only places names reach brew): effective tap present *and in the current scan result* → `"tap/name"`, else the short name. The scan-membership guard is load-bearing: a stale receipt naming a since-untapped tap would otherwise make brew clone it back.
- **Compose** (`composeCatalog()`): core + tap packages deduped by ID — core wins core-vs-tap, alphabetically-first tap wins tap-vs-tap; the loser is invisible in Discover but its installed state joins the winner's card. Recompose rebuilds `catalogIndex` and bumps `catalogGeneration: Int`; `commandIndex` (~60k keys) rebuilds only when the *core* catalog changes — tap formulae have no executables data.
- **`TapStore` scan** — `@concurrent`, zero subprocesses, generation-guarded: taps root from the brew binary's realpath, core clones skipped, brew's own directory rules, line-anchored regex extraction gated on `class … < Formula` / a `cask` stanza, and the **versioned-graveyard rule** (`<base>@*.rb` skipped when `<base>.rb` exists in the same tap unless that exact name is installed — oven-sh/bun ships 165 dead `bun@x.y.z` files that would otherwise bury search).

**Filters** are plain `@AppStorage` state: Discover — kind (`All | Formulae | Casks | Fonts`; Casks excludes fonts so it means "apps"), Hide Deprecated (hides `deprecated || disabled`), From Taps Only; Installed — its own kind filter, Show Dependencies, From Taps Only (effective-tap aware), Pinned Only (the one place every pin is listable at once), and a Name/Date Installed/Size sort. Per-section queries live in `AppModel.queries: [Section: String]` — each `.searchable` binds to its own entry through one model accessor, so queries survive section switches.

### Safety

Destructive capability is **narrow and confirmed**; everything else is **unrepresentable**, not merely un-called. `BrewCommand` is the only source of brew argv:

```swift
enum BrewCommand {
    case listFormulae, listCasks          // reads: ["list", "--formula"|"--cask", "--versions"]
    case outdated                         // ["outdated", "--json=v2"]
    case update                           // ["update"] — the freshness rule's inline check
    case install(name: String, cask: Bool), upgrade(name: String, cask: Bool), upgradeAll
    case servicesList                     // ["services", "list", "--json"]
    case serviceStart(name: String), serviceStop(name: String)  // reversible launchd ops
    case tap(name: String), untap(name: String)                 // brew refuses untap while in use
    case trustTap(name: String), untrustTap(name: String)       // trust confirmed; untrust privilege-reducing
    case autoremove                       // argument-less by construction, confirmed
    case uninstall(name: String, cask: Bool)                    // confirmed, force-less
    case zap(name: String)                // ["uninstall", "--cask", "--zap", name] — receipt-gated, confirmed
    case cleanup                          // exactly ["cleanup"]; files-only under HOMEBREW_NO_AUTOREMOVE=1
    case doctor                           // ["doctor", "--json"] — read; exit 1 = findings, judged by parse
    case link(name: String)               // non-destructive; brew refuses conflicts and rolls back
}
```

- **Unrepresentable**: `--force`, `--ignore-dependencies`, the `remove`/`rm` aliases, cleanup's `--prune`/`-s`/`--scrub`/named targets, services `kill`/`cleanup`/`restart`/`run`/`--all`/`--file`/`--sudo-service-user` and every alias, `untap --force`, `--custom-remote`/`--repair`/`--eval-all`, link's `--overwrite`/`--dry-run`. Tap names are validated to the `user/repo` shape before enqueue.
- **The trust-write rule**: every removal or trust grant reaches the model only after its `confirmationDialog` has run — `uninstall`, `zap`, `untap`, `autoremove`, `cleanup`, `trustTap` and the tap-install trust consent all funnel through a pending-state property the dialog consumes; the model methods document the contract and tests pin that setting the pending state enqueues nothing. `link` is the one named mutation admitted *without* a dialog — the service-toggle bar (non-destructive, reversible, brew self-rolls-back), not the removal bar.
- `BrewClient.run` accepts only a `BrewCommand` — there is no `run(arguments:)`. `Process` execs the brew binary directly, no `/bin/sh -c`, so names are single argv elements with no shell surface; names only ever come from decoded catalog/outdated entries, and `enqueue` rejects names starting with `-`.
- Install/upgrade/uninstall carry the explicit kind flag so brew never disambiguates a name that exists as both.
- `BrewCommandTests` is the tripwire: every case's argv asserted exactly; first token must be in the allowed set; no argv element may match a forbidden token (exact or `token-`/`token=` prefix — how `--zap` coexists with the banned bare `zap`); an exhaustive switch means a new case fails the build until tagged, listed and whitelisted.

### BrewClient

- **Discovery** (init, re-run on ⌘R): `fileExists` at the two known paths; neither → `brewMissing`, and the window shows a `ContentUnavailableView` linking to brew.sh — installing Homebrew mid-session recovers with a Refresh, no relaunch.
- **One core method**: `run(_ command:, onLine:) async throws -> Int32` (plus an optional `onErrorLine` sink — nil merges the streams, which every caller but doctor wants). stdout/stderr each get a `Pipe`; two child tasks iterate `bytes.lines` forwarding to the `@MainActor` callback. Exit is awaited via `terminationHandler` bridged into a continuation — **never `waitUntilExit`**, which would block the main actor, starve the `onLine` callbacks, fill the 64 KB pipe buffer and deadlock brew on write.
- **Cancellation** via `withTaskCancellationHandler` → `process.interrupt()` — SIGINT, the Ctrl-C path brew traps and cleans up after (`brew.rb:22` maps it to exit 130); `terminate()`'s SIGTERM would skip brew's cleanup. Exit 130, or an uncaught-signal exit while cancelled, → `.cancelled`.
- Environment: inherited + the login-shell overlay (memoized `shellEnvironment()`; synchronous readers use `effectiveEnvironment`) + the forced safety vars last; `SUDO_ASKPASS` when mutating. Read helpers accumulate lines and hand off to **static pure parsers** (`parseListVersions`, `parseOutdated`, `parseServicesList`) — testable without a `Process`.
- **Askpass helper**: idempotently written at launch to `Application Support/Brewery/askpass.sh` (chmod 0700) — an osascript `display dialog` following the system auth prompt's grammar (app icon, one line of why, one line on where the password goes, default button "Allow"). It stays osascript because sudo execs the helper as a detached child — a native sheet would need a fifo/URL-scheme round-trip for a prompt that appears a few times a year. The icon path interpolates from `Bundle.main` at write time and is dropped if it contains a single quote (it sits inside single-quoted sh).

### Catalog pipeline

`CatalogStore`, plain struct. **The concurrency note that governs the whole app**: the project builds with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and Approachable Concurrency (`NonisolatedNonsendingByDefault`), under which a plain `nonisolated async` function runs on its *caller's* actor — it does **not** hop off main. Anything that must actually leave the main thread is marked `@concurrent` — the catalog download/decode, `loadCache` (a ~8 MB JSON decode at every warm launch does not belong on the main actor), the receipt sweep, the tap scan, `DiskUsage` walks, `FuzzySearch.rank`, `LoginEnvironment.capture`. `StateSnapshot.load` stays sync on purpose: 69 KB decodes in milliseconds.

1. **Download** — `async let` all five files: `formula.json` + `cask.json` (~48 MB raw), `executables.txt`, both analytics files. At most once a day; no streaming parser (YAGNI). A failed download of any small file degrades its field to nil/empty — the catalog never blocks on them. **Conditional by ETag** (all five endpoints serve `etag` and honor `If-None-Match`, verified live): each request carries the previous cache's validator, and when nothing regenerated server-side — both catalogs 304, each optional file 304 *or failed* (a failure reuses its previously joined values, strictly better than re-decoding with the field emptied; `canReuse`, pinned by `CatalogEtagTests`) — the previous packages are reused wholesale and only `fetchedAt` restamps: no download, no decode. A mixed generation (one file fresh while a sibling 304s — rare, the site regenerates all five together) re-requests the 304'd files unconditionally rather than persisting per-file payloads.
2. **Decode & merge** — throwaway `Decodable` structs declaring only the needed keys. Commands join by formula name; analytics join by name/token (commas stripped); the qualified-name subset of formula analytics is captured as `tapInstalls90d` so compose can join real counts for tap packages.
3. **Cache** — `CatalogCache { version, fetchedAt, packages, tapInstalls90d, etags }` → atomic write to `Application Support/Brewery/catalog.json` (~4.5 MB). `CatalogStore.cacheVersion` (currently **10**) is the schema stamp: a mismatch or decode failure is "no cache" and triggers a fresh download — schema migrations are free. The composed catalog is never written back; the cache holds core packages only. **The etags live inside this versioned file, never beside it** — `fetch()` reads the previous cache itself rather than taking validators from a caller, so a version mismatch or decode failure discards validators and payload together; a validator that outlives its payload would keep earning 304s against a cache that is gone (the observed failure mode in Homebrew's own BrewUI, where the etag sits in UserDefaults apart from the payload and a desync bricks the catalogue until the server's etag moves).
4. **Startup** (`bootstrap`): snapshot + cache published immediately → probes fire concurrently → if `fetchedAt` > 24 h (or no cache), download in background and swap. First-ever launch fills Discover with the working capsule until the first catalog lands — the empty-slot rule, not an overlay.

### Fuzzy search

`FuzzySearch` — pure `score(query:candidate:) -> Int?` and `@concurrent rank(...) -> [SearchHit]`; a hit carries `matchedCommand` so cards can say *why* something matched ("Provides `convert`"). Case-insensitive; per package the score is the max over name, displayName, and — for `tap != nil` packages only — the qualified `"user/repo/name"` string (pinned: a qualified hit never outranks an exact short-name match elsewhere):

| Match | Score |
|---|---|
| exact | 1000 |
| prefix | 900 − candidate length |
| query is exactly a provided command | 850 |
| word-boundary start (after `-` `_` `@` `.` space) | 700 − position |
| query (≥ 2 chars) prefixes a provided command | 600 − command length |
| substring anywhere | 500 − position |
| subsequence | 100 + contiguity bonus |
| name misses, `desc` contains query | 40 |

Command-exact sits between prefix and word-boundary deliberately: typing `convert` almost certainly wants imagemagick, but a formula literally named what you typed still wins. A command hit only counts when its package is in the passed subset (Installed/Outdated must not surface strangers); the browse path wraps its packages in `SearchHit(matchedCommand: nil)` so the grid renders one type. Tie-break: shorter name, then alphabetical. Results cap at 200 — and the subtitle says "Top 200 results", never claiming the cap as the total. An empty query bypasses ranking entirely: Discover browses by 90-day installs (an alphabetical walk of 16k packages opens on "0 A.D." and never reaches anything anyone installs), Installed/Outdated are inventories and stay alphabetical, reports order by their own question (bytes-desc for Storage/Orphans).

Wiring — no Combine: a `.task(id:)` sleeps 50 ms (the `guard` on the sleep matters — a bare `try?` swallows cancellation and the stale task would rank and assign anyway), then ranks off the main actor. Results and browse listings are cached **per section**; the browse key deliberately excludes the query, since the grid still shows the browse listing while a search is being typed.

### Icons

One actor, `IconStore`, keyed by **host** (many packages share a homepage host); generalized to `image(key:url:)` for the avatar tiles.

- `icon(for:)` checks memory → disk → network. The network fetch is a **shared task per host** (in-flight dedup); a view's cancellation abandons the await, never the fetch, so the result always lands in the cache — the fix for `AsyncImage`'s cancel-on-scroll losing grid icons. Not cancelling removes the only in-flight cap, so the cap is explicit: 6 concurrent downloads (async semaphore), a 15 s request timeout, a 5-minute in-memory cooldown after transport failure. **429/5xx count as transport failure** (short cooldown), never as a week-long "no image" marker — rate limiting says nothing about existence.
- **Memory is a plain dictionary, not `NSCache`** — the system purges `NSCache` under pressure without warning and icons were thrashing. **Disk**: bytes-as-received per host file; birthtime = fetch date, mtime = last access (stamped at most daily), both read and written through `URLResourceValues`. Eviction is plain LRU after each write past **50 MB**. A disk hit older than **7 days** serves stale immediately and re-fetches in background. **Negative caching**: a 404/undecodable body writes a zero-byte marker with the same 7-day TTL.
- **Fonts never hit the store** — foundry favicons are meaningless; they always render the `textformat` symbol. **Installed casks with a live `.app` skip it too**: the bundle's own icon via `NSWorkspace.icon(forFile:)`, rendered overscanned by the icon-grid ratio (1024/824) under the favicon clip so both species are geometrically identical tiles. **The forge-host skip**: github.com/gitlab.com homepages wear the kind glyph — one logo repeated across half the catalog is chrome pretending to be identity — with one exception: `github.com/<owner>/<repo>` with **owner == repo** (case-insensitive) is the dedicated-account pattern (`tmux/tmux`), where the avatar *is* the project's identity; `avatarSource(homepage:)` reuses the tap-avatar URL (`github.com/<owner>.png?size=128`) and key namespace, so a tap owner's tile is shared.
- The store's statics are `nonisolated` (an actor's statics otherwise pick up the MainActor default — two hops per fetch). Fallbacks: `terminal.fill` / `macwindow` / `textformat` in a tinted rect; the loading placeholder is the same symbol dimmed — no spinners in the grid.

### State snapshot & the freshness rule

The last-published overlays (`installed`/`outdated`/`serviceStatuses`/`pinned`) are written to `state.json` beside the catalog cache at the end of every `refreshState()` publish (best-effort, atomic, off the main actor) and applied at the top of `bootstrap()` — install state is local knowledge, on screen at first frame, never a probe answer; without it every launch flashed "Install" on the user's own packages for the probe second. The probes then correct silently — the same stale-until-refresh rule the app already runs mid-session, stretched across the relaunch gap. `StateSnapshot` carries its **own version stamp**, independent of `cacheVersion` (that one covers `Package`'s shape; this one covers the overlay structs — bump it when their stored shape changes — optional top-level additions that decode as nil for old files, like `pinned`, need no bump, the catalog cache's tap-field rule); a mismatch or failed decode reads as no snapshot, which is exactly first-launch behavior. The brew-missing refresh persists its emptied overlays too: brew gone is a state, not an error. A skeleton action slot was rejected: placeholders are for what the app doesn't know, and the app knows.

`refreshState()` runs its four independent probes (installed, outdated, services, the pin scan) as `async let` (as do the refresh-while-loading pairs in `bootstrap` and `refresh`), is generation-guarded (a superseded run bails before publishing), and also re-sweeps receipts, rescans taps, and re-stats metadata freshness.

### The operation queue

`operations: [BrewOperation]` (session history) + `enqueue` + a private `pump()` — MainActor, no locks. Only mutating commands queue; reads run concurrently. A mutation enqueues a staleness-gated "Updating Homebrew" ahead of itself when metadata is stale. **Failure policy: continue** — a failed operation surfaces in the popover but never drains or halts the queue. State: `queued → running → succeeded | failed | cancelled`; each log capped at 2,000 lines, with ANSI stripping done **once at ingest** in `BrewOperation.append` (unit-tested there) — a live stream re-evaluates the log view's body once per appended line, so per-render regexing was quadratic.

**The busy hold is generation-aware.** A finished operation keeps its target busy until the post-operation refresh lands (`awaitingRefresh`, consulted by `isBusy` — the `upgradeAll` fan-out included): between completion and the probes landing, the overlays still answer for the old world, and dropping busy on state alone flashed "Install" a beat after installing. Because a superseded refresh bails before publishing, operations stamp the *refresh* generation at completion (`refreshGeneration`, bumped per probe pass — not `catalogGeneration`, which counts composes) and **whichever refresh actually publishes releases every hold stamped before it started** (the brew-missing branch publishes empty overlays and releases the same way) — an unconditional clear could land against pre-mutation overlays and flash exactly the stale answer the hold exists to prevent. `BusyThroughRefreshTests` pins the one spinner → result swap; the release core has its own test.

**Dock integration**: the tile badge carries the outdated count; a failure while the app is inactive bounces the icon (`requestUserAttention(.informationalRequest)`); **success knocks too** — one bounce when a batch drains with at least one succeeded mutation and no failure; a mixed batch bounces once via the failure path, never twice. Badge and failure bounce live **in the model** (the badge as a `didSet` on `outdated`, the bounce where `failureToPresent` is set) — Dock reporting must work with zero windows, and both once rode ContentView. The Dock menu offers Refresh and Update All (n).

**Quit**: `applicationShouldTerminate` confirms while a mutation is running *or queued* (a queue held behind the freshness check must not be silently discarded) — the alert says "in progress", keeps Return on the destructive Quit (Safari's order) and gives Keep Running the Escape equivalent. On confirmed quit the running brew gets `interrupt()` and up to 5 s; queued operations are discarded.

**Disk measurement** (`DiskUsage`) backs the pane's Size row, the reports and the size sort through one session cache keyed `id|version` (old kegs under `oldkeg:` keys — one key must never mean two measurements) plus an **in-flight registry**, so the pane, the orphan bar and the size sweep share one walk per keg instead of racing duplicates (check-then-act across an await). Walks check cancellation every 512 entries; a cancelled sweep never publishes its partial map (a wipe would erase already-measured sizes and rebuild the listing on nothing) — and because of that, the sweep must be re-entrant rather than guarded: `.task(id:)` cancels the old body without awaiting it, and a walk that only notices cancellation every 512 entries kept a Bool guard raised long enough for its own replacement to bail and never retry. `isMeasuringSizes` is therefore a count (`isChecking`'s shape), and overlapping sweeps share one walk through the in-flight registry. Symlinks are never followed — a keg's bin links would double-count or escape the root. The whole cache flushes on cleanup completion. The attention headline reads `attentionCount` — a count computed straight off the catalog, never a catalog-scale array build in a view body.

### The deterministic UI-test harness

Mutations and error paths are UI-testable without touching the machine: the harness (modeled on Homebrew's BrewUI, whose design and failure modes are the citations here) fakes exactly two process boundaries — the brew subprocess and the network — so everything in between (queue, `Process` exec and streaming, parsers, reconcile, render) runs for real, and an error case is a fixture file, not test-only code.

- **Activation is payload presence.** `UITestMode` (app target) answers off one lazy static: nil unless `BREWERY_UITEST_PAYLOAD` is in the launch environment — production launches are inert by construction, and there is no separate flag to misorder. A malformed payload `fatalError`s with the reason: silently falling through to the real machine is the one unacceptable failure mode.
- **The runner names, the app writes.** The test picks a root under `/tmp` (`BREWERY_UITEST_ROOT`) and ships the fixture tree as `base64(zlib(JSON))` in the payload variable; the app creates every directory and writes every byte, fake brew included (written + `chmod 0700`, the askpass treatment). Learned upstream and re-confirmed here: the OS lets the runner *read* app-written files but not write them (EPERM), and runner-written files may be unexecutable by the app — so exactly one process owns the tree. Sibling env vars (`XDG_CONFIG_HOME`, `HOMEBREW_CACHE`, `HOMEBREW_LOGS`) point into the root and reach brew children through the ordinary merge because the harness skips the login-shell capture (whose overlay would otherwise shadow them — and source the developer's dotfiles).
- **Fake brew is a lookup table**, not a switch: argv joined by `_` keys `<key>.stdout/.stderr/.exitcode` files; a successful run copies `<key>.apply/` into a state overlay consulted first, which is how "install succeeded" changes what the four probes answer next — through the app's real reconcile. A missing fixture exits 64 naming the path it wanted. `installBrew: false` is the brew-missing scenario, and the discovery seam makes it an interlock: a harness launch resolves only the fake path, never the machine's brew.
- **The network stub** (`UITestStubURLProtocol`, installed per-session — never `registerClass`, which would capture `.shared`) serves `<root>/http/` fixtures keyed by request path with `/`→`_`, honors `.status` siblings, and answers a matching `If-None-Match` with a real 304 when a `.etag` sibling exists — the catalog's conditional branch runs end to end. Unfixtured paths 404, which for icons is the deterministic glyph-fallback path.
- **Five seams, all behind `UITestMode.active`**: brew discovery, the login-shell skip, `CatalogStore.supportDirectory` (one redirect covers `catalog.json`, `state.json`, `Icons/`, `askpass.sh`), the catalog download session, the icon session.
- **Test side**: `UITestScenario` renders one `FixturePackage` into every wire format at once — catalog entry, `list --versions` line, `outdated --json=v2` entry — so a scenario cannot disagree with itself, and always renders the whole read-only surface so a missing fixture cannot surface as an unrelated error state. The payload budget is 256 KB with a failure that says to shrink the scenario, not raise the limit. `UITestModeTests` pins the wire format, the fixture-key grammar and the fake-brew script contract headlessly, because no source file is shared between the app and UI-test targets.
- The pre-existing suite (perf pins, machine-state smoke) keeps running against the real machine; `HarnessTests` is the hermetic set.

## UI structure

**Scenes**: a single `Window` ("main", `.defaultSize(1200 × 780)`, 1000 pt minimum so the sidebar, two card columns and the pane fit at the floor) — plus one value-only `WindowGroup` for per-operation logs (resizable, live-tailing, operation as title, state as subtitle, Cancel in the toolbar, listed in the Window menu; no default value, restoration off — operations are session state) — plus the `MenuBarExtra` (its own section below). **The app stays running after the last window closes**: its point is a background operation queue, so ⌘W closes the window and the queue runs on — the Dock badge keeps counting, and clicking the Dock icon reopens the window (AppKit's default, restored by deleting the terminate-on-close override).

**Shell**: `NavigationSplitView`. Sidebar: Discover (`sparkle.magnifyingglass`), Installed, Outdated (badge: count), Services (`server.rack`, badge: running count), Taps (`spigot`), then a titled **Reports** group — Orphans, Attention, Storage (`internaldrive`), Checkup (`stethoscope`) — no badges: a passive report is not pending work. Selection, pane/popover visibility, `selectedPackage` and `selectedTap` all live in `AppModel`, not view `@State` — a `Commands` builder can only reach app-level state, and every time that rule was forgotten the workaround was a monotonic request-counter side-channel with order-dependent `onChange` handlers. Sidebar section and inspector visibility persist across launches.

**File layout** — flat in `Brewery/`, one file per surface or system; filesystem-synchronized groups, so never touch `project.pbxproj` for files:

| File | Responsibility |

**Windowed rendering and the listing grammar.** The slice is taken in `ContentView` and the grid is handed only the cards it draws plus a total count — **the load-bearing part**: a view's stored properties live in SwiftUI's attribute graph, which copies and diffs them on every update, so passing the full `[SearchHit]` and rendering `prefix(window)` cost ~6 s per keystroke even though only 60 cards were drawn (measured: 6.34 s → 0.51 s). The window starts at 60 and a sentinel inside the `LazyVGrid` extends it by 60. `ListingToken` (in `ContentView`) spells the eleven listing-defining fields **once** — section, every filter, the sort, the drilled tap and its transient kind filter (the query is *not* one of them; it rides `WindowToken`) — and `BrowseKey`/`SearchKey`/`WindowToken` build on it, as does the grid's `.id`, so the scroll offset restarts on exactly the changes that restart the render window, with the re-rank generations and counts deliberately beside it, never inside: `catalogGeneration` stays out of `WindowToken` because a recompose must never reset the scroll window. Browse listings and search results are cached per section, so revisits render on the first frame; the build task skips outright unless an input in the key actually changed.

**Cards**: 44 pt icon; name; pills for identity (kind tag, tap-owner tag — owner segment only, core untagged), then one `·`-joined plain-text run for version and state (App Store's metadata grammar); 2-line description; "Provides `cmd`" on command hits; trailing control — `Install`/`Update` prominent, an Installed label with green check (state wears no button chrome — a disabled button reads as broken), `Open` bordered for single-bundle and font casks, a bare small spinner when busy (no cancel affordance at card size — halting lives on the surfaces that own the queue). Deprecated cards paint the same orange the pane's banner uses — a still-installable package must not look identical to a disabled one. A hidden height-reserving twin keeps mixed rows flush. Selection is the accent border + tint wash (a custom grid has no system selection to lean on); only a single `Package.ID?` crosses the view boundary. Context menus everywhere carry `PackageMenuItems`.

**Detail** is a non-modal `.inspector` pane (min 300 / ideal 340 / max 480), open by default, persisted, toggled by ⌘I; No Selection placeholder when nothing is chosen; `.id(package.id)` so a different card starts a fresh stack, while re-selecting the shown package's card pops to root via the selection funnel. Content: header (stats share one fixed-glyph-column row helper; Size measures on visit with an in-place redacted placeholder, memoized per `id|version`; the license line collapses to a count row when its sample can't fit one line), font preview for installed font casks (six representative faces, round-robin by family, Regular first, remainder stated — Font Book is the specimen browser, reachable via Open), caveats through `CaveatFormat` (backticks → inline code, indented runs → copyable code blocks, `$HOMEBREW_PREFIX` substituted at display time, `brew install` mentions resolved into `RelatedRow`s — the page's own package excluded by full ID), Commands (inline `·`-run at ≤ 8, else a count row pushing a Commands page, case-insensitively sorted), Contents for casks (payload only — plumbing like zap/manpages deliberately dropped), Conflicts, Dependencies / Required By from receipts, Other Versions (the @-family: same kind and base name, numeric-aware order, bare name first — built into page `@State` by a task, never a catalog scan in body), the Service section, the operation log. Pushes ride a **manual ZStack page stack** — pages stay mounted so back restores the parent's scroll, hidden pages are `.disabled` and `.accessibilityHidden`, and the stat-column grammar is fixed: secondary text everywhere, `chevron.right` navigates deeper, `chevron.down` discloses below, `arrow.up.forward.app` leaves the app. The tap stat row pushes a tap page bounded at a 30-row most-installed shelf with **Browse All in Taps** below it (a cap is only honest if it keeps the most relevant rows). Open goes through `NSWorkspace`/LaunchServices — the launched app is its own process, no brew involvement.

**Toolbar** (trailing edge, sectioned by two fixed `ToolbarSpacer`s so the text-labelled action doesn't read as part of the icon cluster): the section-scoped tier (Filter menu, Sort menu, Update All) · the app-wide pair (Refresh, Operations) · the inspector toggle. The Operations button shows a spinner + count while active and a red `exclamationmark.triangle.fill` after a failure — a *different glyph*, not just a red one, so the failure survives dismissal and color-blindness; its accessibility label composes the state ("Operations, N running" / "Operations, last operation failed"). Two AX rules earned here: the label content is `.accessibilityElement(children: .ignore)` because a bare `ProgressView` in a toolbar label hoists itself out of the AX tree and the button vanishes for VoiceOver — and the content is bare images/stacks, never `Label`, because the toolbar bridge adopts a `Label`'s *title* as the item's AX label, outranking every accessibility modifier: the failed state read as a plain "Operations" with the tell living only in the pointer-only tooltip, against the tooltip rule, until `HarnessTests.testFailedInstallPresentsTheFailure` caught it. The popover (Safari's Downloads) lists operations with Cancel on the running one, remove on queued ones, Show Log per row, and Clear (keeps queued, running, and still-awaiting-refresh operations — removing those would drop the busy hold mid-window). It auto-presents once on failure.

**Menu bar** — every toolbar action has a menu bar command and a key equivalent; menus always show the same item set, `.disabled` where inapplicable (never conditionally included):

- **View**: the nine destinations as Toggles (⌘1…⌘5 library, ⌘6…⌘9 reports — the checkmark is "you are here"; switching one *off* is meaningless, so only `true` acts); **Back** ⌘[ — one owner: the tap page wins while open (the committed content-column rule), otherwise the pane pops via a model channel; **Filter** — one stable item set: a Kind picker bound to whichever section is on screen, each toggle dimmed where its section isn't current, the menu disabled elsewhere; **Sort By** (⌃⌘1…3, Installed-only, disabled elsewhere — Finder's sort-by modifier family); **Show/Hide Info** ⌘I and **Show/Hide Operations** ⌥⌘L (Safari's Downloads shortcut — the popover this app's queue surface grew from) — titles name the state they will produce.
- **Homebrew** (app-specific — these act on Homebrew, not the view): Refresh ⌘R · Update All ⇧⌘U · "Uninstall *title*…" ⌘⌫ (dynamic title, disabled when nothing uninstallable is selected) · "Pin/Unpin *title*" (dynamic title and verb, no ellipsis — no dialog follows) · Run Checkup ⇧⌘K · Clean Up… · Remove All Orphans… · Cancel Operation ⌘. (the platform's cancel, aimed at the queue's one running operation) · Add Tap… · "Remove *tap*…" (dynamic title). The ellipsis items open the same confirmation dialogs their content buttons do.
- **Edit ▸ Find ▸ Find…** ⌘F focuses the search field via `.searchFocused` — wired explicitly; the automatic `.searchable` binding has been inconsistent on macOS.
- **Help** is replaced (`CommandGroup(replacing: .help)`) with links to docs.brew.sh and its FAQ.
- User-facing strings say **Update** everywhere; `BrewCommand` keeps brew's own `upgrade` in argv.

**Menu bar extra.** The stays-running decision's other half: with the window closed the app still knows about updates, and the menu bar is where that knowledge lives. A `MenuBarExtra` scene (`.menu` style — HIG *The menu bar*: "Display a menu — not a popover — when people click your menu bar extra"), sharing the one `AppModel`, content in `MenuBarMenu.swift`. Presence is the user's call (HIG: "Let people — not your app — decide"): `isInserted` binds `@AppStorage("menubar.shown")`, default on, with **Hide Menu Bar Icon** in the extra's own menu and a state-named **Show/Hide Menu Bar Icon** twin in View — re-enabling must never need the icon that's gone. Every item mirrors an existing command; nothing is extra-only ("Avoid relying on the presence of menu bar extras").

- **Label**: the `mug` symbol, plus one state in the text slot beside it — the outdated count when updates wait (the Dock badge's sibling), or a static `↻` while the queue runs (the menu bar's own working grammar: Time Machine and the Finder sync arrows change glyph, never animate — and a rasterized label animates unreliably anyway). Animation-free (no Reduce Motion branch owed); one composed accessibility label ("Brewery, N updates available" / "…, N operations running") because bare composed labels degrade in the AX tree (the toolbar Operations button's lesson).
- **A status item's label renders exactly one `Image` and one `Text`.** Anything past that is dropped in silence: the queue tell first shipped as `Text(Image(systemName: "arrow.triangle.2.circlepath"))` in the title slot and rendered as a bare mug for five commits — the AX label was still right, so only geometry catches it (24 pt tall; 34 pt wide icon-only, 51 pt with the adornment), which is what `OperationsSurfaceTests.testMenuBarExtraShowsQueueAdornment` pins. A second `Image` in an `HStack` or as the `Label`'s title fails the same way. Hence a *character*, not a symbol — U+21BB resolves inside `.SFNS-Regular`, the same font at the same weight as the count digits it replaces, where U+27F3 falls back to AppleSymbols and reads as a foreign icon font.
- **The `isInserted` trap**: the preference binding must be change-guarded, never `$menuBarShown` raw — see the appendix entry on the re-render loop.
- **Menu, top-down**: a disabled status row (the Outdated footnote's `lastCheckedCaption` grammar — "Everything is up to date · checked N ago" / "N updates available"; while the queue runs, the Operations button's own count phrase — accurate for mixed batches, one vocabulary; computed on open, no timer: `.menu` content rebuilds per open, and menus are exactly where periodic scheduling proved unreliable). Then up to five outdated packages, "name installed → current", each enqueuing its upgrade — upgrades never need the trust-consent dialog (install is the only consent gate), so no extra item can ever require the window-attached dialogs — with an overflow item opening the window on Outdated. Then **Update All** (⇧⌘U shown for recognition; the binding lives in the Homebrew menu), **Open Brewery** (`NSApp.activate()` then `openWindow("main")` — a status-item click doesn't make the app frontmost), **Check for Updates** (the ⌘R path, disabled while refreshing), **Launch at Login**, **Hide Menu Bar Icon**, **Quit Brewery** (activate first, or the quit-guard alert appears behind other apps).
- **Launch at Login** is a checkmark toggle over `SMAppService.mainApp`, the app's first behavior preference. `status` is not observable and opening an extra's menu does not activate the app, so the checked state is read fresh each menu open — the extra's menu is the only surface that shows it, so a change made in System Settings is current by the next open and no other resync exists. Registration happens only on an explicit toggle — macOS shows a system notification on register, so never speculatively — and `.requiresApproval` routes to `SMAppService.openSystemSettingsLoginItems()`. Meaningful only from an installed `/Applications` build; DerivedData registrations go stale.
- **Login launch is silent**: launched as a login item, the app starts with the menu bar icon only and no main window — the window opens on demand. Prerequisite: `bootstrap()` starts from app startup, not the window's `.task`, so the model runs windowless.

**Background update check.** Owned by `AppModel` (an unstructured task started at the top of `bootstrap()`, before its first await) so it survives window closure. Every 6 hours — and on `NSWorkspace` wake — when no queue is active and no refresh is running, it takes the *gentle* path: the staleness-gated metadata check plus a `refreshState()`, the bootstrap shape. Deliberately **not** the forced ⌘R `refresh()`: force is the explicit-request semantic, and a cadence that forced `brew update` past the staleness gate would spend network and churn every 6 hours for no one. The pass is not invisible — any state work in flight spins the toolbar glyph (`isChecking`), which is the whole of the feedback a background pass earns. `Task.sleep`'s continuous clock runs through system sleep, so a long sleep fires the tick immediately on wake — harmless behind the same guards. **The interval is a cadence, not the timer's period**: the timer's ticks and the wake trigger share one `lastBackgroundCheck` stamp through `shouldBackgroundCheck`, because brew's 450 s staleness window is the wrong coalescer for a laptop — gated on that alone, every lid-open more than eight minutes long spent a `brew update` and a full re-probe, which is "every wake", not "every 6 hours". The stamp is seeded in `bootstrap()` (the launch check is the first tick) and written *before* the pass runs, so a second wake landing mid-pass sees the clock already advanced. A `last` in the future — a clock moved backwards — reads as due rather than blocking the check forever. Because the model must now speak with zero windows, its Dock reporting lives in the model, not a view: the badge is a `didSet` on `outdated`, and the failure bounce fires where `failureToPresent` is set — a failed background batch with the window closed was previously fully silent, and the auto-present handler consumes a stored failure on window reopen (`initial: true`; a plain `onChange` misses values set while unmounted).

**Dialog grammar.** Every confirm echoes its trigger's verb ("Uninstall", "Clean Up", "Remove All", "Remove Tap", "Trust Tap and Install"); destructive actions carry `role: .destructive`; every dialog has a `role: .cancel` button; messages state consequence plus reversibility, sample dependents rather than dump them (≤ 4 in full, else three and a count — ca-certificates is required by half the Cellar), and disclose brew's quirks (multi-keg peeling, trust surviving untap, zap's shared-file warning). **Statements aren't questions**: a blocked uninstall ("bat is still needed") and a blocked tap removal are acknowledged with OK, the cancel role keeping Escape — a confirmation whose only button is Cancel is a question with no yes. **One removal funnel per object kind**: every uninstall surface sets `pendingUninstall`, every tap-removal surface sets `pendingTapRemoval` (which also pops a drilled-in tap page back to the list), installs needing trust set `pendingInstall` — and all the dialogs live on **ContentView's root**, so menu items can present them from any section; `CleanupButton` and the orphan bar are pure triggers. Install's label grows its ellipsis (`Install…`) exactly when the consent dialog will appear. Pinned packages are blocked *before* the dialog (items hidden, command disabled) — brew's pinned refusal exits 0 having removed nothing, and a lying success is worse than a hidden item. The privilege-reducing Untrust ships no dialog; Pin/Unpin likewise — non-destructive and mutually inverse, the service-toggle rule.

**Empty states.** Absence titles are Title Case noun phrases (the system's own No Results shape — "No Services", "Your Taps"); positive outcomes stay sentences (Software Update's grammar — "Everything is up to date", "Nothing needs attention", "Ready to Brew"). Each section's `ContentUnavailableView` wears its own sidebar symbol; the sole action is always `.borderedProminent`; re-scan is **Check Again**, retry-after-failure is **Try Again** — and a listing that filters emptied offers **Clear Filters** instead (resetting that section's own keys; Check Again could never fix it). The empty state rides an overlay on `ReportListView` so the header keeps the list's own gutter. Tips gate on their own TipKit status so dismissal leaves no permanent empty band. Full-window states: "Homebrew not found" with a brew.sh link; "Couldn't load catalog" + Try Again when no cache and the download failed.

**Search honesty.** Return acts only on a landed ranking — never on whatever browse card happens to be first. The taps list counts what `TapsView` renders (tap rows, before the package-search guard). Checkup's ⌘F filters finding boxes by text and affected names; its subtitle counts findings, special-cased before the generic results grammar. Counts live in `.navigationSubtitle` (Mail's spot): browsing shows totals, an active search shows results.

**Reports are lists, not grids** — a report answers "what is this item's state and what does it cost me", so `ReportListView` renders `StateRow` chrome (32 pt icon, title, state line, trailing value) with system `List(selection:)` + `.tag` routed through the one selection funnel (nil/⎋ ignored — the inspector owns "nothing is selected"), the summary bar riding as an ordinary first row so gutters agree by construction. Per report: Storage rows say "N old versions" + old-keg bytes, Orphans rows the desc (orphans are the catalog's obscure corners) + whole-rack bytes, Attention rows the `attentionPhrase` + installed version. Storage's bar is the platform's **storage gauge** (System Settings › Storage): a `title3` total, a 10 pt capsule of proportional categorical segments with a 3 pt minimum sliver — proportions measured against the fillable track, the HStack's gaps deducted first, so a tiny component can never push the last segment past the trailing edge — and a swatch-dot legend that speaks for the (accessibility-hidden) gauge, joined with non-breaking spaces so a narrow bar wraps only at the `·` separators. Bytes measure in one `.task` and publish once. Storage deliberately overlaps Orphans on a different axis: old versions of packages you keep vs whole packages nothing needs — a package can appear in both and both statements stay true. The Attention pane banner says *why* (brew's own humanized reason tables, `deprecate_disable.rb`), *since when*, *when it stops working* (disable date, else deprecation + brew's 12-month `REMOVE_DISABLED_TIME_WINDOW` phrased as "around"), and *what to use instead* as a tappable replacement row.

**Checkup** owns four states: intro with the one prominent Run Checkup (disabled while the queue is active — doctor mid-mutation would report transients as problems — and while a run is in flight: the model guard already no-ops a re-click, and an enabled button that does nothing lies), the wait while running — previous findings stay on screen while the header caption narrates ("Checking…" beside a small spinner, the Outdated freshness caption's grammar) and the bare capsule replaces a claim state (`checkupHasContent`: a wait may only occupy space that has nothing to show) — "Ready to Brew" (brew's own phrase) with the last-checkup time, findings. The outcome is session-only model state — a stale verdict restored at launch would be a lie with a green checkmark. Each finding is a `FindingBox` **keyed by its text** (offset keys re-purposed row state — hover, avatars — whenever the ⌘F filter changed membership), fed by a pure, resolver-injected `FindingPresentation` beside `Remedy`: finding text and remediation prose run through `CaveatFormat.blocks`, so indented command runs become copyable `CodeChip`s in every finding; remediation blocks dedupe against the `commands` array and the `links`; a lone-URL block renders as a `Link`; the box reads top-down as brew wrote it (problem, prose, commands). Two findings get richer structure by first-line sentinel, **degrading to the plain chip on any mismatch** (a reworded header must cost only polish, never data): PATH shadowing resolves shadowed tools to their *providing packages* via readlink of `<prefix>/bin/<tool>` (`commandIndex` ∩ installed as fallback), precomputed in `ingestCheckup` — a view builder can't await readlinks — and published atomically with the outcome; untrusted taps become `TapTile` rows navigating to the tap page, **where the confirmation-gated Trust action already lives — navigate, don't duplicate**. `Remedy` sends exactly four shapes native — `brew link` (in-row Link button, queue-derived states, no dialog: the service-toggle bar), cleanup (the shared `CleanupDialog`), untap (**Show in Taps** — removal keeps its blocking UX on the surface that owns it), install/upgrade (rows selecting into the inspector) — and is stricter than the caveat parser on purpose: any flag beyond the tolerated set aborts to a chip, so `brew install --force foo` never dresses up as a clean row. Remediation commands are **copyable, never executable — the whitelist is the reason**. An unreadable payload degrades to one box with brew's raw text plus a `brew doctor` chip. `-demo-checkup` seeds canned findings through the same ingest path for the screenshot loop.

**Services** rows follow Login Items: icon, title, humanized run command (monospaced, `$HOMEBREW_PREFIX` substituted), status caption that speaks only when it has something to say (green "Running", orange "Scheduled", red "Failed (exit N)"), trailing `Toggle` — disabled with "Requires root — manage in Terminal" for `require_root` services. On-flip enqueues `serviceStart`/`serviceStop` (tap-qualified, no inline update — nothing package-related changes). The pane's Service section shares the same `ServiceToggle`; the Logs row opens in Console once the file actually exists.

**Taps**: the list keeps **real keyboard selection, transient by design** (focus split from activation — arrows move the highlight, Return opens, and the push clears it: a navigation list keeps no highlight after back, while an always-nil selection getter used to drill on every arrow press). **Every row is a whole-cell button** (`DrillRow`: row insets zeroed, the `.inset` gutter — 16 pt/4 pt, measured — relocated inside the label behind a full-width `contentShape`), so a click anywhere on the row is consumed by the button and opens the tap without painting selection; a tap gesture over a shape smaller than the List's selectable band once left the separator strip ghost-selecting — HIG *Lists and Tables*: "Provide appropriate feedback when people select a list item." The `.inset` style's structural row margin (~10 pt outside the cell) is the one region no button can own — a click there still sets List selection, and an `onChange` guarded by `NSApp.currentEvent` converts exactly the mouse-set case into the same push (key-set selection stays: that is the arrows' highlight; this is why drilling-on-arrow cannot return). The button fuses each row into one AX element with a press action — one VoiceOver stop, `'homebrew/core, 8 564 formulae'` — which is also why UI tests query tap rows as `buttons`, never `staticTexts`. Rows wear the System Settings drill-row chevron: these rows push a page, and they say so. Built-ins sit pinned with catalog counts, implicitly trusted, not removable — no per-row "Built-in" pill, the section header says it once; third-party rows carry `TapTile` avatars (owner from the *remote*, never the tap name — custom remotes exist; non-GitHub remotes keep the spigot glyph). **Trust on rows is exception-only** (quiet when all is well): a trusted tap says nothing, an untrusted or partially-trusted one speaks in the Services rows' dot-caption grammar (`StatusDotLabel`, orange), and the full trust story stays on the tap page banner and Checkup. The tap page header carries the pane's ellipsis-menu twin with **Remove Tap…** and **Untrust** — actions must not hide exclusively in a context menu. Remove Tap… is disabled with an explanation while the tap's packages are installed (brew would refuse anyway; the UI declines to enqueue doomed work). The add-tap popover validates `user/repo` live and states the clone URL and trust consequence. The drill-down swap is an instant cut (the list stays mounted beneath for scroll; the page's listing is prefilled synchronously so the cut never lands empty). Tap pages carry a transient per-page kind filter — a persisted filter that silently empties the next tap's page would read as data loss.

**Install trust consent**: installing a qualified tap item makes brew trust that recipe persistently, so when the grant would be new — tap in the scan, not whole-trusted, item not individually trusted (URL-shaped custom-remote entries conservatively re-ask) — the install funnel presents: **Install** / **Trust Tap and Install** (the FIFO queue guarantees the `.trustTap` grant lands before the install starts) / Cancel. Trusted-tap installs show no dialog; the tooltip carries the heads-up.

**Newcomer explanations** in two grammars, split by what the sentence is: *vocabulary* (read once, then dead weight) is a dismissible TipKit card — formulae vs casks atop Discover, "Taps are package catalogs" atop the tap list; *consequences of a control* stay on the control as a `.help` tooltip plus matching `accessibilityHint` — tooltips explain the consequence, never restate the control's name, and anything a tooltip says must exist in the accessibility tree too (tooltips are pointer-only).

**Motion and materials.** Every animating site reads `accessibilityReduceMotion`: x-axis slides become crossfades, blurs drop, `.symbolEffect` repeats hold still, `CopyButton`'s symbol replace and the operations count's numeric roll included. Animation is sparse and only hides rough edges — icons crossfade in, the card's control blur-replaces between install/spinner/check, the grid never animates rearrangement (a reshuffle per keystroke is noise, not feedback), and the titlebar subtitle cannot animate (AppKit-rendered). Glass belongs to the chrome layer: `WorkingCapsule` renders in a standard material because it lives in content. Hierarchical fills use semantic styles (`.quinary`), not literal alphas; warning washes strengthen and gain a border under Increase Contrast; nothing depends on color alone.

**The design language** — one rule, one home (`SharedControls.swift`): **one selection** (`List(selection:)` + `.tag` everywhere a list exists; cards keep their wash because a grid has no list to draw selection for), **one row** (`StateRow` for lists — 32 pt tile, title over caption, accessory slot, title-aligned separators; `PaneRow` for pane density, shared by `RelatedRow`), **one wait** (**the work never takes the content**: the toolbar Refresh glyph spinning on `isChecking` is the app's one global work tell; `WorkingCapsule` is the only working chip and appears only in slots with nothing to show — claims are replaced, never overlaid; inline `ProgressView`s remain as indicators-in-place; values redact), **one state word** (`StatusDotLabel` — colored dot + secondary caption, spoken only when the state says something; Services rows, the service sheet's quiet label and tap-row trust exceptions all name states through it), **one box** (`.contentBox()` — padding 14, radius 12, continuous curvature on fill and stroke), **one menu base** (`PackageMenuItems`: Open Homepage / Copy Name / Pin↔Unpin while installed / divider / Uninstall… — App Store's Delete-last), **one dialog grammar** (above). Pane stat rows are real `Label`s so a wrapping value keeps its glyph on the first baseline; homepage links wear `globe` (Apple restricts the `safari` symbol to Safari itself); tiles share `PackageIconView`'s `ScaledMetric` so one row grammar grows together.

## Invariants (and the tests that enforce them)

- **The safety whitelist** — every brew argv comes from `BrewCommand`; no raw-argument path exists. `BrewCommandTests` pins every case's argv exactly, whitelists first tokens, forbids destructive tokens (exact or `token-`/`token=` prefix), and its exhaustive switch makes a new case fail the build until tagged and listed.
- **Confirmed-before-enqueue (the trust-write rule)** — setting a pending state enqueues nothing; `UninstallFunnelTests` pins the funnel, and the zap choice (`--zap` only for a cask whose receipt earned it) is a `nonisolated static AppModel.uninstallCommand` asserted on the returned `BrewCommand` — the suite never enqueues real uninstalls against the machine running it.
- **The join rule** — overlay keys are `kind:shortname`; `ParsingTests` pins a tap-qualified formula `full_name` joining beside a short cask token, and `ReceiptTests` pins `source.tap` normalization.
- **Cache version discipline** — bump `CatalogStore.cacheVersion` whenever `Package`'s stored shape changes; `CatalogV3Tests` pins the current value and requires the *exact* mismatch error (`keyNotFound("version")` — a broad throws-check pinned nothing). Optional additions that decode as nil for old caches need no bump. `StateSnapshot` has its own independent stamp (`StateSnapshotTests`).
- **No large arrays across view boundaries** — the attribute graph copies and diffs stored properties; `BreweryUITests` pins search focus < 1 s, keystroke < 0.5 s, scroll < 1 s. The pins sit near the dev machine's noise floor: A/B interleaved before blaming a change, and never relax a threshold to green a suite.
- **View invalidation off `catalogGeneration`**, not counts — a tap rescan can change the catalog at equal size; `catalogGeneration` stays out of `WindowToken` so a recompose never resets the scroll window.
- **The busy hold survives until a refresh publishes** — `BusyThroughRefreshTests` pins the one spinner → result swap; the generation-release core has its own test.
- **A refresh never takes the content** — stale listings stay sharp and interactive; `HarnessTests.testListingStaysInteractiveDuringRefresh` pins hittability and a pane answer mid-refresh, `PaneRegressionUITests` pins the claim-replacement half.
- **UI tests must not write the user's defaults** — state is pinned per-launch through the argument domain (plist literals for Bools, verified to coerce through `object(forKey:) as? Bool`); the suite waits for cards (`waitForCatalog`), never fixed sleeps.
- **A harness launch never touches the real machine** — discovery resolves only the fake brew (nil = brewMissing, not fallthrough), the support directory redirects wholesale, and both URL sessions route to the fixture stub; `UITestModeTests` pins that the harness is inert without the payload variable, and mutation flows are UI-tested only through `HarnessTests` scenarios.

## Deliberate deviations

Each of these contradicts a default or a first-read of the HIG, holds for a recorded reason, and was re-audited against the current guidance. All re-affirmed 2026-08.

- **A single `Window` scene, not `WindowGroup`** — one catalog, one serialized queue, one set of filters: a second primary window would be the same app twice with no independent state. HIG *Windows*' "option to view content in a new window" is satisfied by the per-operation log `WindowGroup` — a textbook auxiliary window, value-only so File ▸ New Window stays absent.
- **The app stays running after the last window closes** — ⌘W closes the window, the queue survives, the Dock badge keeps counting, the Dock icon reopens the window. Maintainer decision 2026-08: an app whose point is a background operation queue must not die with its window.
- **File ▸ New Log Window is accepted** — the log `WindowGroup` contributes it even without a default value; it opens the designed No Operation state, and every suppression (`.commandsRemoved()`, an empty `.newItem` group) takes the whole File menu down with it, Close ⌘W included.
- **No `Settings` scene** — HIG *Settings* says to prefer letting people modify task-specific options in place and to minimize settings. Most persisted preferences are task-specific view options (filters, sort, sidebar section, inspector visibility) living on their surfaces; the two app-level behavior preferences the menu bar presence introduced — Launch at Login and Show Menu Bar Icon — live *where the behavior is visible*: in the extra's own menu and the View menu. Two menu toggles do not earn a Settings window.
- **Count text beside the menu bar icon** — the HIG's menu-bar-extra guidance is silent on adorning the symbol; Battery's percentage is the system precedent, and the count is the one datum the extra exists to surface. The menu's status row and the Dock badge carry the same number for the moments the icon is hidden.
- **Dynamic package rows in the extra's menu** — the main menu bar's rule is "always show the same set of menu items", but menu bar extras are the documented home of live content (Wi-Fi's network list, Battery's per-app blame), and the Dock menu here already shows "Update All (n)" conditionally. The command tail below the divider stays fixed.
- **A text status row, not a spinner, for background activity in the extra** — HIG *Progress indicators* prefers an indeterminate spinner for background operations, but `.menu`-style extras render real `NSMenu` items and cannot host a `ProgressView`; the disabled text row states the same fact in the menu's native grammar.
- **`.searchScopes` rejected** — a scope control materializes only while a search is active, and the kind filter has to govern empty-query browsing just the same (it pre-filters the array handed to ranking); a scope bar is also one dimension, while the filters compose three orthogonal ones (kind, deprecation, tap origin). A source is not a kind.
- **`.searchSuggestions` rejected** — the result grid re-ranks live within the pinned < 0.5 s keystroke budget and shows the actual packages with *why* they matched; a suggestion list would be strictly less information for strictly more input. `.onSubmit(of: .search)` supplies the keyboard path.
- **Manual ZStack page stack, not `NavigationStack`** — macOS `NavigationStack` performs no push animation in a split-view detail column (established by screen recording), and a stack inside an `.inspector` pane has no toolbar to hang a Back button from. The hand-rolled version pays its debts: ⌘[ wired through the menu bar, hidden pages `.disabled` + `.accessibilityHidden`, pages stay mounted to preserve scroll, both transitions branch on Reduce Motion.
- **`CommandGroup(replacing: .help)` with doc links** — the app ships no help book, so the stock "Brewery Help" item would only produce an error dialog; docs.brew.sh is the help an app that fronts brew actually needs. (Mechanism note, corrected on audit: AppKit's Help-menu *search field* also searches the app's own menu items and is not what `.help` replaces.)
- **`Toggle`-as-destination menu items** — an inline `Picker` is the idiomatic construct for mutually exclusive items, but `.keyboardShortcut` cannot attach to a `Picker`'s options, and ⌘1…⌘9 / ⌃⌘1…3 are why these items exist in the menu bar at all; the Toggle form draws the same you-are-here checkmark and satisfies the same-items rule via `.disabled`.
- **Hand-rolled windowed grid rendering** — `LazyVGrid` lazily *renders* but does not lazily *cross the view boundary*; the platform ships no replacement for slicing before the boundary, and the perf pins are the proof it's still needed.
- **TipKit for one-time vocabulary** — HIG *Onboarding*'s "collection of context-specific tips instead of a single onboarding flow" is precisely this shape; TipKit supplies the native card, the persisted dismissal and the filled-variant symbol.
- **Detail as a non-modal `.inspector` pane, not a sheet** — reading about a package is not a task to complete or abandon; as a sheet it had accumulated a footer, a back button, a swipe-back monitor, a focus sink and three hardcoded heights — an app inside the app. The split-view selection rule is honored by the selected card's accent border and wash.
- **osascript `display dialog` askpass, not an in-app sheet** — a mechanical constraint, not taste: `SUDO_ASKPASS` must name an executable that sudo execs as a detached child; a SwiftUI sheet would need a fifo or URL-scheme round-trip for a prompt that appears a few times a year. The dialog follows alert grammar.
- **Confirmation dialogs, not undo, for irreversible brew operations** — HIG's escape hatch from confirmation is undoability, and none of these are undoable: `uninstall` discards a built keg, `cleanup` deletes cached bottles, `untap` deletes the clone. Each dialog independently satisfies the button rules (verb-echo, destructive role, cancel role).

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| pkg-cask sudo hangs/fails with piped stdio | `SUDO_ASKPASS` osascript helper + `HOMEBREW_NO_ASK=1`; a cancelled dialog fails fast with a readable log line |
| `HOMEBREW_NO_AUTO_UPDATE=1` → stale metadata (a lying Outdated section) | the freshness rule: launch, ⌘R and mutations run `brew update` first whenever the payload mtime exceeds brew's own 450 s window; terminal updates count via the same mtime; offline falls back silently with one attempt per window |
| ~48 MB raw JSON decode (peak a few ×) | `@concurrent`, transient, ≤ 1×/day; the slim cache makes normal launches instant |
| user runs brew in Terminal mid-operation | brew's flock fails our op immediately with a readable error — surfaced, not retried |
| a probe crashes brew-side (observed 2026-08 on master: `list --cask --versions` raised `uninitialized constant Cask::CaskLoader` while `list --formula` was fine — froze every uninstalled formula at "Installed") | the installed probe degrades **per kind**: the failed side keeps its previous entries, the fresh side publishes wholesale; both failing reads as offline and keeps everything (`AppModel.mergeInstalled`, pinned by `InstalledMergeTests`) |
| `api/internal/executables.txt` is undocumented and could move | failure degrades to empty `commands`; brew's local cache copy is a known fallback |
| installing a tap item auto-trusts it persistently (brew-side, `trust.rb:116-145`) | consent at the moment of consequence: the trust-consent dialog runs before enqueue whenever the grant would be new; no other trust writes exist |
| untrusted-tap installed formulae vanish silently from `brew outdated` (`formula.rb:2649-2655`) | accepted: such items look up to date and Update All skips them; installing anything from the tap via Brewery trusts it and restores visibility; the login-shell overlay keeps the app and the terminal agreeing about *which* taps are trusted |
| a stale receipt naming a since-untapped tap would make brew re-clone it | qualification requires the tap in the current scan; otherwise the short name is passed |
| same short name in two sources | deterministic winner (core, then alphabetically-first tap); the loser's installed state joins the winner's card |
| services exit codes lie (warnings exit 0) | never trust the code: the post-operation `refreshState` re-reads `services list --json` |
| untrusted-tap services vanish from `services list` (brew-side bare `rescue`) | accepted; the section is defined as "what brew reports" |
| `require_root` services started as user warn, then fail later | the toggle is disabled with a "requires root" caption instead of offering a start that lies |
| trust entries survive untap and reapply on re-tap (brew-side) | disclosed in the removal dialog |
| "already tapped" exits 0 silently | the post-op rescan is the truth, not the exit code |
| pinned uninstall exits 0 having removed nothing (`onoe`, not `ofail`) | never enqueued: every surface blocks pinned packages before the dialog |
| multi-version uninstall removes only the default keg, exits 0 | disclosed in the dialog; a repeat uninstall peels the remainder; `--force` stays unrepresentable |
| the receipt-built dependents map misses cask dependents | the block list unions installed casks' catalog `depends_on` claims; brew remains the final arbiter and refuses *before removing anything* |
| a user `brew.env` overrides our safety env vars | treated as defaults, not invariants; the whitelist (which `brew.env` cannot touch) carries the hard guarantees |
| Remove All Orphans with a pinned orphan in the set | brew lists it ("Autoremoving …"), removes the rest, exits 0 (`cleanup.rb:941-949` → the uninstall refusal) — accepted like the pinned-uninstall trap: the dialog discloses "Pinned packages will be skipped.", the post-op rescan is the truth, and the surviving row wears its "pinned" text |
| argument-domain seeding shadows `@AppStorage` writes in UI tests | tests that must *change* filters must not seed those keys at launch, and must reset any touched defaults afterwards (`defaults delete one.metafates.Brewery <key>`) |
| `SMAppService.status` drifts (user toggles in System Settings; not observable, not KVO) | the checked state is read fresh on every menu open (the only surface that shows it); registration only ever happens on an explicit toggle |
| login-launch detection (the `keyAELaunchedAsLogInItem` Apple event) vs SwiftUI's window presentation timing | prototyped before commitment; the recorded fallback is the window opening at login until the suppression mechanism is proven — silent start is the goal, not a claim |

## Appendix: observed failures worth remembering

"We tried X and it broke Y" knowledge not recoverable from the code.

- **The `preferredMaxLayoutWidth` layout loop**: an `NSViewRepresentable` that mutated its view inside `sizeThatFits` dirtied AppKit's constraints per sizing query; a fixed-width sheet converged and hid it, a resizable pane threw "more Update Constraints in Window passes than there are views in the window". Any representable here must measure without touching its view. (The representable is gone — native `Text(AttributedString)` replaced it — but the trap outlives it.)
- **macOS `NavigationStack` does not animate pushes in a split-view detail column** (iOS does) — the reason every drill-down here is manual; a pushed page's listing must be prefilled synchronously before `withAnimation` or it slides in empty and reads as a cut.
- **An auto-hidden `TipView` leaves ghost state behind**: sharing a tree with `ContentUnavailableView.search` it blanked the surface, and inside a `List` a dismissed tip left its section insets as a permanent empty band — gate the row on the tip's own `statusUpdates` so a dismissed tip contributes nothing.
- **The argument-domain trap**: a leading bare launch flag (`-demo-operation`) swallows the next `-key` as its *value* — seed `-key value` pairs first, bare flags last.
- **Menu items are queryable without opening their menu**, so an assertion on a File-menu item can "pass" against a closed menu binding a label the items don't carry — and the click-then-requery shape hangs the runner mid-menu-tracking. Assert on bound elements (Close queryable, no New Window exists), or open the menu and wait for it before asserting.
- **The login-shell trust breakage**: launched from Finder without `XDG_CONFIG_HOME`, brew read the wrong trust store — every terminal-trusted tap read as untrusted, their formulae silently ignored by every command the app ran, and doctor invented PATH findings about launchd's PATH. Environment parity is correctness, not cosmetics.
- **`setEventHandler` for `kAEOpenApplication` kills every window**: registering an open-application Apple-event handler (to sniff `keyAELaunchedAsLogInItem`) replaces AppKit's own open handling, and no launch — Finder, `open`, XCUITest — presents a window at all. Login-launch detection must read `NSAppleEventManager.shared().currentAppleEvent` inside `applicationDidFinishLaunching` instead; the event is current exactly there.
- **`MenuBarExtra(isInserted: $someAppStorage)` is a re-render loop**: the scene writes the current value back through the binding on every update, a same-value `@AppStorage` write invalidates the scene, and the whole app re-renders per frame — main thread pegged at 100% in `NSRunLoop.flushObservers`, surfaced by the UI-test runner as "has not loaded accessibility / main thread busy 30 s" while the app *looked* fine. Diagnosed with `sample` by bisecting the scene; the fix is a change-guarded `Binding` (write only when the value differs). The label and menu content were innocent — first suspicion fell on the ViewBuilder label and was wrong.
